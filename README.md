# 115tools

基于 115 网盘的 Emby 媒体库同步工具：**让 Emby 的媒体库"看起来"在本地，实际存在 115 上，且你不需要管**。

视频上传 115 → 本地替换为 `.strm` 直链 → Emby 通过 `/download` 播放（命中本地缓存则直读，否则回源 115 CDN 流式透传）。本地目录与云端目录互为镜像，新增、改名、删除都会自动对齐。

> **免责声明**：本项目由 AI 编程助手编写生成。请在使用前自行评估风险，部署与使用产生的一切后果由使用者自行承担。

## 功能

- **任务中心** — 卡片式管理任意数量同步任务。每个任务绑定一对「本地目录 ↔ 云端目录」，用一组平铺开关描述要做什么，不再区分 push/pull 两种互斥类型：
  - 本地 → 云端：上传新增/变更（含文件事件监听、静默窗口、视频/STRM 立即同步）、定时执行
  - 云端 → 本地：下载缺失文件、清理云端冗余、完成后归档到回收目录
  - 收尾方式：视频落地为 `.strm`、上传后原件移入本地缓存（关 = 删除）
- **预演（dry-run）** — 任务卡片「预演」按钮：只算计划不执行，按动作类型分组列出将要发生的一切，删除/归档类动作红色标记并二次确认。**动云端之前先看会发生什么。**
- **最近动态** — 只留「值得看的事件」（执行起止 / 触发方式 / 计数 / 错误）；明细日志在 `docker logs`
- **离线下载** — 添加 http / magnet / ed2k 链接或上传种子文件，下载到 115 指定目录
- **透传本地缓存** — 上传完成的视频按 pickcode 暂存本地，`/download` 播放命中本地即跳过 115 回源
- **执行记录** — 每次执行留结构化事件，任务卡片「动态」按钮可回看

## 使用说明

### 必填全局设置

启动后在「设置」页填写以下 **4 项必填**，缺一项同步不会启动（缺失项在任务中心顶部横幅提示，补全保存后自动开始）：

| 配置项 | 用途 | 示例 |
|--------|------|------|
| `refresh_token` | 115 开放平台刷新令牌，换取访问令牌 | — |
| `strm_url` | STRM 链接前缀（`/download` 直链地址） | `http://设备IP:端口号` |
| `temp_dir` | 云端回收目录（清理视频时移入，可找回） | `/Temp` |
| `cache_dir` | 本地透传缓存目录（上传视频暂存，命中直读） | `/mnt/cache` |

### 任务中心

全局设置保存后，新建任务时先选一个场景预设（三选一，自动预填开关，可再进「高级选项」微调）：

- **把媒体库搬到 115**：本地视频上传，换成本地 `.strm`（上传 + 监听 + 视频立即同步 + STRM + 移缓存 + 定时）
- **把 115 的片拉回本地**：云端新增落地为 `.strm`，然后归档到回收目录（下载 + STRM + 归档 + 定时）
- **双向镜像**：上传 + 下载都开，保持两边一致

### 日常操作约束

同步以「本地文件为准」：本地由监听 + 定时扫描自动上传 / 清理云端；云端只用来「放新文件进来」。

- **云端侧**：只允许「新增」；禁止对已有文件删除、移动、重命名、覆盖。
- **本地侧**：可新增 / 删除 / 移动 / 重命名，程序自动同步到云端。
- 想动云端的东西，先在本地对应位置操作，再让程序同步上去；拿不准就先点「预演」。

## 部署

```yaml
services:
  115tools:
    image: ghcr.io/ytx-zhang/115tools:latest
    container_name: 115tools
    environment:
      - TZ=Asia/Shanghai
      - LOG_LEVEL=INFO            # DEBUG / INFO / WARN / ERROR（明细日志见 docker logs）
    volumes:
      - ./config/:/app/data          # 数据目录（config.json / sync.db）
      - /path/to/media:/media        # 本地媒体目录（在任务里填 /media 这类容器内路径）
    ports:
      - "8080:8080"
    restart: unless-stopped
```

启动后访问 `http://your-server:8080`：Web 面板先于同步启动，即使配置不完整也能打开；「设置」填齐 4 项必填后，同步引擎自动启动。

## 架构速览

```
webui（HTTP + SSE + 前端） → engine（全局单队列 + 触发源） → mirror（领域核心） → drive / store / conf
```

- `mirror/plan.go`：**纯判定**——本地现状 × 索引 → 动作清单，不碰网络与文件系统（可单测、可预演）
- `mirror/apply.go`：唯一有副作用的地方（建目录 / 上传 / 接管 / 清理 / 下载 / 归档）
- `engine/queue.go`：全局单消费者队列，上传天然串行，去重合并由队列承担
- `store`：单个 bbolt 库（`sync.db`），索引记录显式携带 Kind 与 PickCode，`.strm` 一致性判定比 pickcode 而非 mtime
- 日志：标准库 `slog → stdout`（docker 负责存储与轮转）
