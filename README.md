# 115tools

基于 115 网盘的 Emby 媒体库同步工具：本地文件自动上传云端、云端文件同步到本地、批量生成 `.strm` 直链文件。

登录方式：**开放平台**（`refresh_token`），在 Web 设置页填写并保存。

> **免责声明**：本项目由 CodeBuddy（AI 编程助手）100% 编写生成。请在使用前自行评估风险，部署与使用产生的一切后果由使用者自行承担。

## 功能

- **本地文件自动同步** — 监听本地目录变化，自动上传新增/修改的文件到 115 网盘，视频文件上传后自动转为 `.strm` 直链
- **云端文件同步** — 查找并清理云端同名 / 重复文件（主要用途），附带把云端多出文件下载到本地或生成 `.strm` 直链
- **STRM 批量生成** — 从指定 115 目录批量生成 `.strm` 文件，配合 Emby 实现网盘视频直链播放
- **离线下载** — 添加 http/magnet/ed2k 链接或上传种子文件，直接下载到 115 网盘指定目录
- **Web 管理面板** — 实时进度展示、一键触发同步/生成任务、日志查看
- **定时全量同步** — 定时自动执行本地 + 云端全量同步（默认 12 小时，可在设置页调整间隔或关闭）

## 使用说明

### 首次启动要求（重要）

**本地同步根（sync_path 对应的云端 / 本地目录）在第一次启动时必须为空**。

程序首次启动会扫描云端同步根建立本地数据库索引，随后本地同步（启动时自动运行 + 定时全量）会以「本地文件为事实源」进行比对：**凡 DB 中记录、但本地不存在的文件，会被判定为「本地已删除」并清理云端**（视频移入云端回收目录、普通文件直接从云端删除不可找回）。

> 注意：云端**媒体库（strm_path）**里放已有视频是安全的——那是给「STRM 生成」用的，不写本地同步 DB，原始视频会被移到回收目录而非删除，不会触发上面的误删。

因此——

- **云端同步根为空、本地也为空**：标准用法，安全。
- **想「从本地迁移」**：先把原有视频放进本地同步根、云端同步根保持为空，再启动。本地同步会自动上传并在本地替换为 `.strm`。
- **云端媒体库已有视频、想转成 `.strm`**：走「STRM 生成」（见下方数据迁移），由云端媒体库生成 `.strm`，不依赖本地同步，不会误删。

简言之：第一次启动时，**云端同步根**必须为空；只有云端媒体库（strm_path）放已有视频是安全的（走 STRM 生成）。

### 日常操作约束（重要）

`sync_path` 以**本地文件为事实源**：本地由实时监听器 + 本地同步自动上传 / 清理云端；云端则只当作「新增入口」，其它改动一律回到本地做，由程序同步反映到云端。两边边界如下：

**云端（115 网盘侧）的 `sync_path`：只允许「新增」**

- **允许**：在 115 网盘侧往同步目录放新文件 / 新文件夹，回到面板点「云端同步」即可下载到本地或生成 `.strm`。
- **禁止**：在云端对已有文件执行删除、移动、重命名、覆盖编辑。云端不是事实源，这些改动程序不会跟随同步，会造成云端与本地 / DB 长期不一致，且难以自动修复。

**本地 `sync_path`：可以新增 / 删除 / 移动 / 重命名，程序会自动反映到云端**

- **新增**：把文件放进 `sync_path`，监听器自动上传；若担心云端重复，再点「云端同步」去重核查（云端同步主要就是查找并清理云端同名 / 重复文件，下载云端多出文件只是顺手）。
- **删除**：直接删本地文件，下一次本地同步会把对应云端文件一并清理——视频移入云端回收目录（可找回），普通文件直接从云端删除不可找回。
- **移动 / 重命名**：在本地操作即可，监听器会把新位置当作新文件上传到云端（云端新增），旧位置的云端文件由本地同步清理。

一句话：**想对云端做任何事，先在本地对应位置操作，再让程序同步回去；云端目录本身只当「放新文件进来」的入口。**

### 目录命名规则（重要）

**Docker 挂载到容器内的目录名，必须与 `config.json` 里的云端目录名（`sync_path`/`strm_path`）完全一致**，因为代码根据本地文件路径直接映射云端路径。

例如 `config.json` 中 `sync_path` 为 `/strm媒体库`、`strm_path` 为 `/待刮削`，则 `docker-compose.yml` 的 volumes 必须这样写：

```yaml
volumes:
  - ./media:/strm媒体库     # ✅ 正确：与 sync_path 同名
  - ./strm:/待刮削          # ✅ 正确：与 strm_path 同名
```

如果写成 `- ./media:/media`，程序会查找云端路径 `/media`，必然匹配不上。

### docker-compose.yml

```yaml
services:
  115tools:
    image: ghcr.io/ytx-zhang/115tools:latest
    container_name: 115tools
    environment:
      - TZ=Asia/Shanghai
      - LOG_LEVEL=INFO            # DEBUG / INFO / WARN / ERROR
    volumes:
      - ./config/:/app/data                           # 配置文件目录
      - /path/to/media:/strm媒体库                     # 本地同步根目录（必须与 sync_path 同名）
      - /path/to/strm:/待刮削                          # strm 生成本地目录（必须与 strm_path 同名）
    ports:
      - "8080:8080"
    restart: unless-stopped
```

> **关键**：Docker volumes 冒号右边的容器内路径，必须与 `config.json` 中 `sync_path`、`strm_path` 的值**字符完全一致**。

### 配置文件

本地配置文件 `<数据目录>/config.json` 由程序自动创建与维护，**所有配置项均通过 Web 管理面板填写**，无需手动编辑。

**获取 Token（开放平台）**：只需在面板填写 `refresh_token` 一项，`access_token` 和 `expire_at` 留空即可——程序启动后会自动获取并周期性刷新、回写。

### 修改 STRM URL 前缀

在「设置」页修改 `strm_url`（STRM 链接前缀）并保存后，程序会**自动批量**把本地已有 `.strm` 文件的链接地址规范化到新前缀（遍历 sync_path 与 strm_path 两棵目录树）。

重写时**保留文件修改时间（mtime）**，因此：

- Emby 不会把 strm 误判为变更而重新扫描媒体库；
- 本地同步按 mtime 比对，不会误触发「删旧视频 + 重传」。

批量重写会触发文件监听事件（每个 strm 一次轻量检查后即跳过），属于预期的小额开销；strm 文件很多时保存配置会多一次目录遍历。

### 数据迁移

已有数据的媒体库按以下方式植入：

**从本地迁移（已有本地视频，想上传到 115 不再占用本地空间）**

1. 确保云端目录为空，本地目录为空
2. 启动 115tools，完成初始化，管理面板确认正常运行
3. 将原有视频文件移动到本地挂载目录（如 `/strm媒体库/电影/xxx.mp4`）
4. 文件监听器会自动检测 → 上传到云端 → 本地替换为 `.strm` 文件
5. 非视频文件（字幕、nfo）上传后本地保留原文件

**从云端迁移（已有云端视频文件，想转为本地 `.strm`）**

1. 确保云端视频位于**云端媒体库（strm_path 对应的云端目录）**，云端同步根（sync_path）保持为空。
2. 启动 115tools，完成初始化（仅建索引，本地仍是空的）。
3. 在管理面板点击 **「STRM 生成」**：程序扫描云端媒体库 → 在本地 strm_path 目录生成 `.strm` 索引文件，并把云端原始视频移入云端回收目录（TempPath，不删除、可找回）。**注意：STRM 生成只写 strm_path 区域、不写本地同步 DB。**
4. 将本地 strm_path 下生成的 `.strm` 文件**移动到本地同步根 sync_path**（Emby 媒体库目录）。
5. 文件监听器（或手动「开始扫描」）检测到 sync_path 下的 `.strm` 在同步 DB 中无记录 → 作为**新增文件**上传到云端同步根并写库对齐（此时云端同步根本就为空，不会触发「删云端」）。

> 此路径全程不会触发「本地空 → 删云端」：原始视频进了回收目录（可找回）；`.strm` 移入 sync_path 后因同步 DB 无记录被当作新文件上传，与初始化时同步根的索引互不冲突。

**从其他 115 strm 项目迁移**

如果旧 `.strm` 文件内部链接包含 pickcode（URL 中有 `pickcode=` 参数），可直接迁移：

1. 云端视频文件保留在原位不动
2. 启动 115tools，完成初始化
3. 将所有旧 `.strm` 文件按目录结构**全部复制**到本地 `sync_path` 目录下
4. 程序会自动解析 pickcode 找到对应云端视频，移动到正确位置并重写 `.strm` 链接
