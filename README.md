# 115tools

基于 115 网盘的 Emby 媒体库同步工具：本地文件自动上传云端、云端文件同步到本地、批量生成 `.strm` 直链文件。

> **免责声明**：本项目由 CodeBuddy（AI 编程助手）100% 编写生成。请在使用前自行评估风险，部署与使用产生的一切后果由使用者自行承担。

## 功能

- **本地文件自动同步** — 监听本地目录变化，自动上传新增/修改的文件到 115 网盘，视频文件上传后自动转为 `.strm` 直链
- **云端文件同步** — 查找并清理云端同名 / 重复文件（主要用途），附带把云端多出文件下载到本地或生成 `.strm` 直链
- **STRM 批量生成** — 从指定 115 目录批量生成 `.strm` 文件，配合 Emby 实现网盘视频直链播放
- **离线下载** — 添加 http/magnet/ed2k 链接或上传种子文件，直接下载到 115 网盘指定目录
- **Web 管理面板** — 实时进度展示、一键触发同步/生成任务、日志查看
- **定时全量同步** — 定时自动执行本地 + 云端全量同步（默认 12 小时，可在设置页调整间隔或关闭）
- **透传本地缓存** — 上传完成的视频按 pickcode 暂存到本地，Emby 通过 `/download` 直链播放时命中本地可跳过 115 上游回源，省流量、降延迟

## 使用说明

### 必填配置

启动前需要在 Web 设置页填写以下 **5 项必填配置**，缺任何一项同步都不会启动（缺失项会在面板顶部高亮提示，补全保存后无需重启即自动开始同步）：

| 配置项 | 用途 | 示例 |
|--------|------|------|
| `refresh_token` | 115 开放平台刷新令牌，换取访问令牌 | — |
| `sync_path` | 本地媒体文件同步根（Emby 媒体库目录） | `/strm媒体库` |
| `strm_path` | STRM 生成输出目录（对应云端媒体库） | `/待刮削` |
| `temp_path` | 云端临时回收目录（清理视频时移入，可找回） | `/Temp` |
| `strm_url` | STRM 链接前缀（`/download` 直链地址） | `http://设备IP:端口号` |

### 首次启动要求（重要）

**本地同步根（sync_path 对应的云端 / 本地目录）第一次启动时必须是空的**。

程序首次启动会扫描云端同步根，之后本地同步（启动时自动运行 + 定时全量）以「本地文件为准」进行比对：**只要某个文件程序有记录、但本地已经没有了，就当作「本地已删除」去清理云端**（视频会移入云端回收目录、普通文件直接删除不可找回）。

> 注意：云端**媒体库（strm_path）**里放已有视频是安全的——那是给「STRM 生成」用的，原始视频会移入回收目录而不是删除，不会触发上面的误删。

因此——

- **云端同步根为空、本地也为空**：标准用法，安全。
- **想「从本地迁移」**：先把原有视频放进本地同步根、云端同步根保持为空，再启动。本地同步会自动上传并在本地替换为 `.strm`。
- **云端媒体库已有视频、想转成 `.strm`**：走「STRM 生成」（见下方数据迁移），由云端媒体库生成 `.strm`，不依赖本地同步，不会误删。

简单说：第一次启动时，**云端同步根**必须是空的；只有云端媒体库（strm_path）放已有视频是安全的（走 STRM 生成）。

### 日常操作约束（重要）

`sync_path` 以**本地文件为准**：本地由实时监听 + 本地同步自动上传 / 清理云端；云端只用来「放新文件进来」，其它改动都回本地做，由程序自动同步上去。两边边界如下：

**云端（115 网盘侧）的 `sync_path`：只允许「新增」**

- **允许**：在 115 网盘侧往同步目录放新文件 / 新文件夹，回到面板点「云端同步」即可下载到本地或生成 `.strm`。
- **禁止**：在云端对已有文件做删除、移动、重命名、覆盖。这些改动程序不会跟着同步，会导致云端和本地长期对不上，而且很难自动修好。

**本地 `sync_path`：可以新增 / 删除 / 移动 / 重命名，程序会自动同步到云端**

- **新增**：把文件放进 `sync_path`，监听器自动上传；如果担心云端有重复文件，再点一次「云端同步」去重（云端同步主要就是查找并清理云端同名 / 重复文件，下载多余文件只是顺带的功能）。
- **删除**：直接删本地文件，下一次本地同步会把对应的云端文件一并清理——视频移入云端回收目录（可找回），普通文件直接从云端删除不可找回。
- **移动 / 重命名**：在本地操作即可，监听器会把新位置当作新文件上传到云端，旧位置的云端文件由本地同步清理。

一句话：**想动云端的东西，先在本地对应位置操作，再让程序同步上去；云端目录只负责「放新文件进来」。**

### 透传本地缓存

视频文件上传到 115 完成后，**不再删除本地原件**，而是按 pickcode 分目录移入本地缓存目录 `<同步根目录>/.cache/<pickcode>/<原名>`（缓存与源同挂载点，移入走原子 rename；原 `<数据目录>/cache` 旧位置已废弃）。

Emby 通过 `/download` 直链播放（透传模式，即空 UA 或 `Lavf/*`）时，程序先查本地缓存：

- **命中**：直接流式回传本地文件（支持 Range/206，自动按切片供前置 nginx 缓存），**跳过 115 上游回源**，省回源流量、降低首包延迟。
- **未命中**：照常向上游 115 取链并回源。
- **302 分支**（浏览器/播放器直接下载）仍走 CDN，**不命中本地缓存**。

缓存保留期由 Web 设置页「**缓存保留天数**」控制（默认 1 天，填 `0` 回退默认；到期由清理协程自动回收）。保存即实时生效，无需重启。

> **缓存目录排除**：缓存目录固定为 `<sync_path>/.cache`，刻意置于同步根内以保证与源同挂载点、原子移动。文件监听器（fswatcher 原生 per-path 排除）与本地扫描器均固定忽略该目录，不会把缓存视频当成新增文件重新上传；请勿把其他业务目录命名为 `.cache`。

### 部署

#### docker-compose.yml

```yaml
services:
  115tools:
    image: ghcr.io/ytx-zhang/115tools:latest
    container_name: 115tools
    environment:
      - TZ=Asia/Shanghai
      - LOG_LEVEL=INFO            # DEBUG / INFO / WARN / ERROR
    volumes:
      - ./config/:/app/data                           # 配置文件目录
      - /path/to/media:/strm媒体库                     # 本地同步根目录（必须与 sync_path 同名）
      - /path/to/strm:/待刮削                          # strm 生成本地目录（必须与 strm_path 同名）
    ports:
      - "8080:8080"
    restart: unless-stopped
```

#### 目录命名规则（重要）

**Docker 挂载到容器内的目录名，必须和 `config.json` 里的云端目录名（`sync_path`/`strm_path`）完全一致**，因为程序用本地文件路径直接对应云端路径。

例如 `config.json` 里 `sync_path` 为 `/strm媒体库`、`strm_path` 为 `/待刮削`，则 `docker-compose.yml` 的 volumes 必须这样写：

```yaml
volumes:
  - ./media:/strm媒体库     # ✅ 正确：与 sync_path 同名
  - ./strm:/待刮削          # ✅ 正确：与 strm_path 同名
```

如果写成 `- ./media:/media`，程序会去找云端路径 `/media`，自然就对不上。

> **关键**：Docker volumes 冒号右边的容器内路径，和 `config.json` 里的 `sync_path`、`strm_path` 要**一字不差**。

### 修改 STRM URL 前缀

在「设置」页修改 `strm_url`（STRM 链接前缀）并保存后，程序会**自动把本地已有的 `.strm` 文件链接更新到新前缀**（sync_path 和 strm_path 下的所有 `.strm` 都会处理）。

如果 `.strm` 文件很多，保存后首次同步会稍慢一些（要遍历全部 `.strm`）。

### 数据迁移

已经有数据的媒体库，按下面的方式接入：

**从本地迁移（已有本地视频，想上传到 115 腾出本地空间）**

1. 确保云端目录和本地目录都是空的
2. 启动 115tools，完成初始化，管理面板确认正常运行
3. 把原有视频文件移动到本地挂载目录（如 `/strm媒体库/电影/xxx.mp4`）
4. 文件监听器会自动检测 → 上传到云端 → 本地替换成 `.strm` 文件
5. 非视频文件（字幕、nfo）上传后本地保留原文件

**从云端迁移（已有云端视频文件，想转为本地 `.strm`）**

1. 确保云端视频放在**云端媒体库（strm_path 对应的云端目录）**，云端同步根（sync_path）保持为空。
2. 启动 115tools，完成初始化（本地还是空的）。
3. 在管理面板点击 **「STRM 生成」**：程序扫描云端媒体库 → 在本地 strm_path 目录生成 `.strm` 文件，并把云端原始视频移入云端回收目录（TempPath，不删除、可找回）。
4. 把本地 strm_path 下生成的 `.strm` 文件**移动到本地同步根 sync_path**（Emby 媒体库目录）。
5. 文件监听器（或手动「开始扫描」）发现 sync_path 下新增的 `.strm` → 作为**新文件**上传到云端同步根（此时云端同步根本就为空，不会触发「删云端」）。

> 这条路径全程不会误删云端：原始视频进了回收目录（可找回）；`.strm` 移入 sync_path 后被当作新文件正常上传。

**从其他 115 strm 项目迁移**

如果旧 `.strm` 文件内容里有 pickcode（URL 中带 `pickcode=` 参数），可以直接迁移：

1. 云端视频文件保持原样不动
2. 启动 115tools，完成初始化
3. 把所有旧 `.strm` 文件按目录结构**整体复制**到本地 `sync_path` 目录下
4. 程序会自动解析 pickcode 找到对应的云端视频，移到正确位置并重写 `.strm` 链接
